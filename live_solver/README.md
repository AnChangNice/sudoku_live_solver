# 实时数独求解（摄像头 + AR 叠加）

用摄像头对准纸质数独，页面自动找出九宫格、识别已知数字、求解，并把答案**直接叠加到视频里的空格中**。纯前端实现：画面不上传，手机浏览器也能用。

- PC：Chrome / Edge + USB 摄像头
- 手机：Android Chrome、iOS Safari（必须 HTTPS）
- 同一套页面，无需安装 App

## 快速开始

```bash
cd live_solver
npm install
npm run dev          # http://localhost:5173
```

首次加载会下载识别引擎（OpenCV.js，约 10.8 MB），之后走缓存；页面会显示加载进度。

局域网调试（手机连同一 Wi-Fi）：

```bash
npm run dev:lan      # HTTPS + 监听所有网卡
```

> iOS 可能拒绝不受信任证书下的摄像头权限。手机验收请直接用 GitHub Pages 地址（HTTPS）。

## 使用

1. 点「开启摄像头」，允许权限。
2. 把九宫格完整放进画面并保持稳定（约 0.5 秒）。状态栏依次显示「保持稳定… → 已锁定 → 已求解」。
3. 答案以绿色数字叠加在空格中。移动纸张时叠加会跟随。
4. 点「定格」冻结当前画面并做一次高分辨率识别；再点「继续」回到实时。
5. 有字迹但没认出是几的格子会标成琥珀色，并提示「N 格待确认」。点「编辑」可手动修改；如果那里本来就是空的（影子、反光），点「都当空格」即可。编辑/设置面板按住标题栏（左侧六点）可拖动，拖到一边就能对照原题；重新打开会回到默认位置。
6. 手工改过的格子在回到实时后会保留：同一道题重新识别时以你的修改为准，不会被相机读数覆盖，也不会再反复提示。
7. 没有摄像头时可用「照片」上传/拍摄一张数独图。换一张照片等于换题，之前的手工修改不会带过来。

识别策略偏保守：不确定的格子不会被悄悄当成错误线索。若一道题因个别格子判错而无解，打开「编辑」按红色冲突提示修正即可。

## 实现

```
摄像头/照片
  → 720px 灰度 → 自适应阈值 → 轮廓 → 四边形候选
  → 16 条内部格线覆盖率校验（含粗格线中心偏移）→ 连续 4 帧稳定锁定（卡尔曼滤波平滑 + 逐帧速度预测）
  → 高清抓帧（≤1600px）→ 透视校正 900×900
  → 纯 JS 切 81 格 → Otsu/连通域 → 对比度 + 笔画核门槛判空 → 28×28 归一化
  → 内置 784→96→10 分类器（数字 1–9 + “非数字”）+ 双内缩共识 + 置信度门槛
  → 位掩码 + MRV 回溯求解（冲突/无解/多解/超限）
  → 逐格仿射投影，把答案嵌入视频画面
```

关键点：

- **只在锁定时识别一次**，每帧只做廉价检测，数字不闪烁。
- **同一道题的重读做时序迟滞**：和已确认值不同的读数要连续两次一致才采纳；某次没认出来不会抹掉已确认的数字，也不会弹「待确认」；空格第一次读出高置信数字时立即采纳。
- **锁定后的四边形用卡尔曼滤波跟踪**：每个角点带速度状态（匀速模型），静止时压掉检测抖动，移动时保持跟手、不拖影；解锁或换题时重置。两次检测之间（检测只有十几到几十 fps）还会按速度**外推到当前屏幕刷新时刻**再绘制，把检测/处理延迟补回来——没有这一步，转动镜头时叠加会明显落后于纸面。加速度噪声参数取值偏“跟手”，启动/停止的瞬态滞后只有几像素。
- **屏幕/窗口外框仍会被拒绝**：几乎没移动、但整体放大/缩小 3% 以上的候选不跟随（它们和九宫格同心，角点只偏 1% 左右，距离和面积门槛都拦不住）。这个尺寸门槛只对静止候选生效，真实转动带来的连续透视变化不会被误拦。
- **标准灵敏度下 0.5 分（margin 0.1）即采纳**：实拍屏幕上细笔画的 4、7 常落在 0.5~0.6，次优数字只有 0.1 左右，0.6 的门槛会把大量真实线索标成“待确认”。分不清时仍按待确认处理，绝不硬猜。
- **锁定的不一定是九宫格**（手机屏幕边框、桌面边缘都可能）。读取前的 16 条格线校验不通过就重试，并把失败的四边形冷处理 2.5s，换下一个候选。校验除了要求粗格线（3/6 分位）可见，还会测量它们的亚像素中心：四边形比真实格线大 5% 以上时偏移超过 7px，直接拒绝——否则会锁定到笔记本屏幕外框上，答案按屏幕投影铺满整屏。
- **双读共识**：同一格用两种内缩各读一次，结果不一致就标为待确认。
- **待确认只留给“像数字但拿不准”的格子**：格线残段、手机边框投下的阴影、摩尔纹会同时贴住两条内缩边界，或直接被分类器判成“非数字”，这些按空格处理——否则满屏空格都要用户确认。真实数字在格内居中，最多只贴住一侧。
- **待确认格不盖答案**：它可能是题面上的已知数字。只画琥珀色框，否则会和原字形叠在一起，看起来像“把 4 认成了 2”。
- **数字分类器**随包发布（`src/vision/digit-net.js`，约 440 KB），离线在浏览器里训练：26 种字体、共 96 个字体/字重组合，随机字号/位置/轻微旋转，再叠加降采样、模糊、墨迹粗细、褪色、背景与噪声；另设“非数字”类吸收格线残段与残缺字形。独立评测集上数字准确率 99.6%，且各阈值下没有“读错的数字被接受”。手机数独 App 常用的粗圆体（Fredoka、Baloo 2、Nunito、Rubik）单独加权采样——它们的 3/8、4/9 缺口很浅，样本不够时会被认成别的数字。实拍偏虚的字形依赖训练里的模糊增强，改动数据集后重新训练：`npm run train:digits`（需要本机 Chrome）。
- **不按宽高比过滤四边形**，透视下正方形看起来像矩形。
- 叠加不做整图 warp，而是逐格仿射 + 按设备像素比绘制文字，字迹清晰且跟手。

## 测试

```bash
npm test             # Node 单元测试：求解器、单应、切格、归一化、分类器、滤波（58 项）
npm run test:e2e     # Playwright：合成图管线、启动/摄像头、照片上传、读取失败重试、
                     # 干扰边框不遮挡真数独、真实手机屏幕照片逐格读数（需本机 Chrome）
```

`debug/synthetic.html` 是可视化的合成测试页：渲染已知题目，施加透视/模糊/光照/噪声，跑与生产完全相同的管线，输出检测率、逐格准确率、误判与求解结果。通过 `window.__sudokuDebug` 暴露给 Playwright。

## 部署到 GitHub Pages

仓库已包含 `.github/workflows/deploy.yml`：

1. 仓库设为 **Public**（免费 Pages 要求）。
2. Settings → Pages → Source 选 **GitHub Actions**。
3. 推送到 `master`，工作流会跑单测、构建并发布 `live_solver/dist`。

站点地址：`https://anchangnice.github.io/sudoku_live_solver/`。`base: './'` 不写死仓库名，自定义域名也能用。

## 隐私

所有图像处理都在浏览器内完成，摄像头画面与照片不上传、不落盘。页面不包含统计或第三方脚本；字体与 OpenCV.js 均随站点分发。

## 限制

- 只支持标准 9×9 印刷体，不支持手写体或变体规则。
- 倾斜过大、反光、局部遮挡、低分辨率会影响识别；请让九宫格占画面的大部分。
- 识别引擎首次约 10.8 MB；慢网下需要等待。
- 手电筒、前后摄切换按设备能力显示，不支持的按钮会自动隐藏。

```
  solver.js              位掩码 + MRV 回溯
  vision/                检测、校正、切格、分类器识别、跟踪

  sources/               摄像头与照片
  ui.js  styles.css      中文移动端界面
debug/synthetic.html     合成端到端可视化测试
tools/train-digits.*     浏览器内训练页（由 npm run train:digits 驱动）
e2e/                     Playwright 测试
test/                    Node 单元测试
```
